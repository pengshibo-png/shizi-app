## 你要改的文件

```

```

改完在项目根目录跑一条命令：

```bash
pnpm content:science
```

它会做三件事：校验内容 → 生成 `data/science.json` → 提示你重新生成音频（`pnpm content:audio`）。

## 表格怎么填

共 10 列，一行一条，**必须 90 行**（day 1–90 连续，不能跳号）：

| 列 | 含义 | 限制 |
| --- | --- | --- |
| `day` | 第几天 | 1–90，连续不重复 |
| `week` | 第几周 | 1–13（day 1–7 是 week 1） |
| `theme` | 主题 | 只能从下面 8 个里选 |
| `title` | 标题 | ≤14 个汉字 |
| `body` | 正文 | **60–90 个汉字** |
| `question` | 判断题题干 | ≤20 字 |
| `optionA` | 选项 A | ≤8 字 |
| `optionB` | 选项 B | ≤8 字 |
| `correct` | 正确答案 | 只能填 `A` 或 `B` |
| `explain` | 答完的解释 | ≤40 字 |

**允许的主题**（8 个，不能自创）：

```
用药安全  饮食营养  就医挂号  居家安全  防诈骗  身体运动  自然与环境  生活电器
```

## 三条写内容的硬规矩

**一、写给耳朵，不是写给眼睛。**

老人不认字，正文会被 App 朗读出来。所以：

- 用短句，一句话一个意思
- 用口语："咱们""您""别攒着""记不住就写下来"
- 不用书面语："综上所述""值得注意的是""建议您务必"

**二、一条只讲一件事。**

不要在一张卡里既讲"盐要少吃"又讲"要多喝水"，老人记不住。

**三、具体到一个动作。**

- 差："要注意防跌倒。"
- 好："晚上起夜，先坐在床边停三秒，等头不晕了再站起来。"

## 校验会拦住什么

`pnpm content:science` 不是走过场，下面任何一条都会让它**失败并列出问题行号**，不会把坏内容灌进 App：

- 列名不对或少了列
- day 跳号、重复、超出 1–90
- body 字数不在 60–90 之间
- theme 不在允许列表里
- correct 不是 A 或 B
- 有空的字段

## 改了内容之后还要做什么

```bash
# 1. 校验并生成 science.json
pnpm content:science

# 2. 重新生成科普朗读音频（只补缺的，已存在会跳过）
python packages/content/scripts/build_audio.py --only lessons

# 3. 重新打包
cd apps/learner && pnpm build && pnpm exec cap copy
cd android && ./gradlew assembleRelease
```

## 关于正确答案的位置

脚本会自动把正确答案在 A/B 之间打散（大约各占一半）。这是刻意的：
如果"对"永远在 A，老人全选 A 就能蒙对大多数，家属端看到的正确率就不可信了。
所以你不用自己操心这个，照实填 `correct` 即可。
