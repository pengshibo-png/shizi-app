# 生活百科 · 内容替换说明

> 2026-11-12 起，原来的「科普」模块升级为**生活百科**：从 90 条 8 主题，
> 扩成 **215 条 12 大类**。本文件说明怎么改内容、改完跑什么。
> 旧的 `science.csv` 说明仍适用（它现在是百科的 4 个来源之一）。

## 内容的三个来源

| 文件 | 条数 | 覆盖 |
| --- | --- | --- |
| `packages/content/content/science.csv` | 90 | 最早那批：用药 / 饮食 / 就医 / 居家 / 防诈 / 运动 / 自然 / 电器 |
| `packages/content/content/encyclopedia-phone.csv` | 55 | 手机使用：微信 28 + 支付宝 8 + 手机基础 12 + 常用 App 7 |
| `packages/content/content/encyclopedia-life.csv` | 70 | 金钱财务 20 + 出门在外 18 + 权益法律 18 + 人情往来 14 |

三个 CSV 由 `pnpm content:enc` 合并成 `data/encyclopedia.json`，同时完成：

- 旧 8 主题映射到 12 大类（「生活电器」按内容拆进手机使用 / 居家安全）
- 排推送顺序（**手机使用 → 防诈骗 → 健康类 → 其余**），老人端每天推一条就按这个次序
- 校验：正文 55–95 汉字、判断题答案 A/B 打散（防止全蒙一侧）、大类不缺席、day 连续
- 校验不过就报错并列出问题行号，**不会把坏内容灌进 App**

## 12 大类（`cat` 列只能填这些）

身体运动  自然节气  金钱财务  出门在外  权益法律  人情往来

两份新 CSV 的 `cat` 用的是**子类名**（微信 / 支付宝 / 手机基础 / 常用App / 金钱财务 / 出行 /
权益法律 / 人情往来），构建脚本会归到大类，不用你自己换算。

## CSV 格式

```
cat,order,title,body,question,optionA,optionB,correct,explain
```

| 列 | 限制 |
| --- | --- |
| `cat` | 见上；新 CSV 用子类名 |
| `order` | 类内连续编号 |
| `title` | ≤14 汉字，要具体（好：「往外打视频电话」；差：「微信技巧」） |
| `body` | **60–90 汉字**，会被整段朗读 |
| `question` | ≤20 字判断题 |
| `optionA` / `optionB` | ≤8 字 |
| `correct` | `A` 或 `B` |
| `explain` | ≤40 字，答错时的温和解释 |

UTF-8 无 BOM；字段里有逗号就用双引号包（**建议直接用中文标点，省得转义**）。

## 写内容的三条硬规矩

**一、写给耳朵，不是写给眼睛。** 正文会被朗读出来：短句、口语（「您」「咱们」「别着急」），
不用书面语（「综上所述」「建议您务必」），不用感叹号堆砌。

**二、一条只讲一件事。** 不要一条里既讲充电又讲省电。

**三、具体到能照着做。** 手机类内容必须落到「第几步点什么」：

- 差：「微信可以发照片。」
- 好：「第一步，打开孙子的聊天框。第二步，点右下角的加号。第三步，点相册，挑一张，再点右下角的发送。」

法律类拿不准就写「建议咨询律师 / 打 12315」，**不要编法条编号**。

## 改完跑什么

```bash
# 1. 合并 + 校验，产出 data/encyclopedia.json
pnpm content:enc

# 2. 给新增条目补朗读音频（旧的 90 条复用已有 mp3，不会重做）
python packages/content/scripts/build_audio.py --only enc

# 3. 全量内容体检（字数、音频齐不齐、答案分布、笔顺覆盖）
pnpm content:check

# 4. 重新打包 App
cd apps/learner
node <pnpm> exec vite build && node <pnpm> exec cap copy
node ../../scripts/android-fix.mjs learner
cd android && ./gradlew assembleRelease
```

> 第 2 步的 python 用本机的解释器即可；`build_audio.py` 走 edge-tts，
> 已存在的文件会自动跳过，只补缺的。

## 关于答案位置

构建脚本会自动把正确答案在 A/B 之间打散到接近 50%。这是刻意的：
如果「对」永远在 A，全选 A 就能蒙对，家属端看到的正确率就不可信。
照实填 `correct` 即可，不用自己操心。
