## 一、基础假设修正——这比任何新功能都重要

原规划的核心算术是「90 天 × 20 字 = 1800 字」，它建立在「零基础」上。事实是：

- 会接微信视频 → 她认识大量**操作高频字**（微信视频电话发送语音照片确认取消…）
- 粗估（保守）：1800 字表里她已认识 **132+ 字**；实测量可能 300–600
- **从「一」开始教一个会发微信的人 = 把她当小孩 = 弃用风险最高的一件事**

由此，前两轮评审里「数学摸底」的优先级要**整体升级为第一**，且识字同样需要摸底：

| 原定位 | 修正后 |
| --- | --- |
| 数学摸底 = ★★（缺口4） | **识字+数学摸底 = 第一优先** |
| 节奏问题：20/天 vs 10/天 | **先摸底再定节奏**——生字量都不知道，谈总量为时过早 |

摸底带来的连锁：如果她已认识 500 字，实际生字 ≈ 1300；20/天 → 65 天；10/天 → 130 天。**「90 天」这个数字本身是被零基础假设锚定的，先测再算。**

### 摸底方案（10–12 分钟，一次性，只做首启）

**识字摸底——分层抽样 120 字**（不是全测 1800，老人耐心有限）：

- 592 档抽 40、358 档抽 30、550 档抽 25、补充字抽 25（覆盖难度梯度，能反推总识字量）
- 界面就是她熟悉的「二选一认读」，答错不责备（「这个字咱先记下，以后教」）
- 测完直接产出：`已知字集`（标记已掌握，剔除出字序）+ `待学子列`（保持原教学序）
- 顺带产出家属端第一条有用数据：「奶奶原来认识约 N 字」

**数学摸底——6 题定起点**：

| 3 | 认人民币面额吗 | 跳到「购物找零」 |

数据结构现成（`mathDone` 数组标记即可），只缺题目和界面。
